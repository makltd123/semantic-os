# Архитектура jarvis

Проектный документ. Написан после итерации 1, опирается на замеры из
[RESEARCH_LOG.md](RESEARCH_LOG.md) — каждое решение здесь ссылается на эксперимент,
который его вынудил. Это не описание текущего кода, а то, к чему код должен прийти.

---

## Что должно получиться

> Слой, который превращает расплывчатую устную фразу в правильное действие
> **над текущим состоянием машины** — и честен в том, насколько он уверен.

Три слова здесь несущие:

- **расплывчатую** — человек не обязан помнить формулировку;
- **над состоянием** — «потише» разрешается только знанием, что сейчас звучит;
- **честен** — неуверенность проявляется как вопрос, а не как молчаливо неверное действие.

Чего система принципиально не делает: не ведёт диалог, не решает многошаговых задач,
не кликает по интерфейсам. Это слой ввода, а не агент.

---

## Что замеры уже сказали

Пять фактов, из которых вытекает вся конструкция.

**1. Задержка распознавания — константа, её не убрать (E7, E8).**
~1.0–1.2 с независимо от длины фразы; потоки, опции декодирования, тип вычислений и
облако исчерпаны. Значит архитектура не должна пытаться выиграть эту секунду — она
должна её **structurировать**: всё, что можно сделать заранее или параллельно, делается
заранее, а человек видит прогресс, а не молчание.

**2. Разбор по целой фразе ломается предсказуемо (E4, E4b, H1).**
Эмбеддинг короткой фразы кодирует **тему**, а не намерение. Отсюда две ошибки одного
корня:
- потеря направления: «приглуши» → `volume_up` (сходство 0.80);
- перевес объекта над глаголом: «переключись на браузер» → `app_launch` (0.87).

Порог отрыва их гасит, но ценой покрытия (перефразировки 9/25 → 4/25). Это лечение
симптома. **Корень — сравнение фразы целиком.**

**3. Лучшие решения приходили из состояния, а не из языка (E2, E6).**
«Сделай потише» при нулевой громкости → отказ «громкость уже на нуле».
«Открой проводник» при уже открытом проводнике → переключиться, а не запускать второй.
Обе «ошибки» по моему эталону были правильнее эталона.

**4. Часть фраз двусмысленна по существу (E2, E6).**
«Я отойду», «ухожу на обед» — это либо заблокировать, либо не гасить экран. Ни одна
модель не угадает, потому что угадывать нечего. Сейчас система выбирает наугад, и при
ошибке оставляет компьютер незаблокированным.

**5. Кэш усиливает ошибки (E5).**
Всё выученное срабатывает мгновенно и уверенно — включая выученное неверно.
Скорость обучения и цена ошибки связаны жёстко.

## Целевая архитектура

```
                       ┌──────────────────────────────┐
   речь ──► Слух ─────►│  Разбор: глагол × объект     │
            (STT)      └───────────┬──────────────────┘
                                   │  намерение + уверенность
                       ┌───────────▼──────────────────┐
     ┌────────────────►│  Связывание с миром          │
     │                 └───────────┬──────────────────┘
     │                             │  конкретная цель
┌────┴────────┐        ┌───────────▼──────────────────┐
│ Модель мира │        │  Решение по уверенности      │
│  (с историей)│       │  делать / спросить / отказать│
└────┬────────┘        └───────────┬──────────────────┘
     │                             │
     │                 ┌───────────▼──────────────────┐
     └────────────────►│  Исполнение (+ отмена)       │
                       └───────────┬──────────────────┘
                                   │
                       ┌───────────▼──────────────────┐
                       │  Ответ: плашка + голос       │
                       └───────────┬──────────────────┘
                                   │  исправления
                       ┌───────────▼──────────────────┐
                       │  Обучение (кэш намерений)    │
                       └──────────────────────────────┘
```

### 1. Слух

Без изменений по существу: локальный Whisper `base`, фиксированная секунда.
Архитектурная роль — отдать текст и **освободить время**: пока человек говорит,
модель мира уже обновляется (сделано), а по окончании речи разбор стартует сразу
(авто-стоп по тишине, сделано).

### 2. Разбор: глагол × объект

**Главное изменение против текущего кода.** Сейчас намерение — это `{action, args}`,
где всё смешано. Предлагается:

```python
@dataclass
class Intent:
    verb: str            # что сделать: quieten, launch, focus, close, lock, ...
    target: TargetRef    # с чем: описание, а не готовый объект
    params: dict         # сколько/насколько
    confidence: float    # 0..1, откуда бы ни пришло
    source: str          # exact | fuzzy | semantic | model
```

Сравнение по кэшу идёт **отдельно по глаголу и отдельно по объекту**. Это лечит корень
обеих ошибок из факта 2: «приглуши» и «прибавь» различаются глаголом при одинаковом
объекте; «открой браузер» и «переключись на браузер» — тоже.

Для русского это требует лёгкой морфологии (привести глагол к начальной форме).
Подходящий по весу вариант — `pymorphy3`; проверить стоимость на этом железе.
Если окажется дорого — запасной вариант: словарь глагольных маркеров, собираемый из
якорей.

### 3. Модель мира

Сейчас `snapshot()` — мгновенный срез. Нужна **модель, помнящая прошлое**, иначе
«открой то, где я вчера писал» неразрешимо в принципе (это и есть заявленная цель).

```python
@dataclass
class World:
    now: Snapshot                  # окна, звук, буфер, громкость — как сейчас
    recent: list[Event]            # что открывалось, закрывалось, звучало, копировалось
    def find(self, ref: TargetRef) -> list[Candidate]: ...
```

`Event` — плоский журнал: время, тип, сущность. Пишется фоново, дёшево, хранится
локально (SQLite или JSONL с ротацией). Это единственное новое хранилище.

Важно: **модель мира — не кэш намерений.** Кэш помнит, как ты говоришь; мир помнит,
что происходило.

### 4. Связывание

Отдельный этап, которого сейчас нет — он размазан внутри действий
(`_match_window`, `_live_session`). Вынести, потому что:

- связывание всегда идёт по **свежему** состоянию, даже если намерение из кэша
  (это уже действующее правило: кэш хранит действие, не привязку);
- именно здесь возникает неоднозначность «какой из трёх браузеров», и её надо
  обрабатывать единообразно, а не в каждом действии по-своему;
- здесь же появляется честный отказ по состоянию (факт 3): «нечего убавлять».

Возвращает список кандидатов с весами, а не один объект.

### 5. Решение по уверенности

Сейчас поведение бинарно: сработало или нет. Из фактов 4 и 5 следует три режима:

| Уверенность | Поведение |
|---|---|
| высокая | сделать и коротко сказать что |
| средняя | **сделать, но сказать, что именно понял, и как отменить** |
| низкая | переспросить одной фразой: «заблокировать или не гасить экран?» |

Это прямой ответ на «я отойду»: не угадывать, а спросить. Переспрос дешевле ошибки,
особенно когда цена ошибки — незаблокированный компьютер.

Порог уверенности зависит от **цены ошибки действия**, а не только от сходства:
`lock_screen` и `window_close` требуют больше уверенности, чем `volume_down`.
Значит у действия появляется атрибут «цена ошибки».

### 6. Исполнение и отмена

Из факта 5: всё, что система научилась делать быстро, она быстро делает и неправильно.
Поэтому у действия появляется, где возможно, обратная операция:

```python
@dataclass
class Done:
    action: str
    undo: Callable[[], None] | None
    described: str
```

Голосовое «отмени» откатывает последнее действие; «не то» — вдобавок вычищает
ассоциацию из кэша (уже работает). Для необратимого (`lock_screen`) обратной операции
нет — значит такое действие попадает в категорию высокой цены ошибки и требует
подтверждения.

### 7. Ответ и обучение

Плашка остаётся тем, чем стала: показывает всю цепочку и **почему** система решила
именно так. К этому добавляется отображение уверенности и способа отмены.

Обучение — существующий кэш, но ключом становится пара (глагол, объект), а не строка.

## Что меняется в текущем коде

| Модуль | Судьба |
|---|---|
| `stt.py`, `tts.py`, `audio.py`, `hud.py`, `timing.py` | остаются, правки косметические |
| `state.py` | расширяется до `world.py`: снимок + журнал событий + `find()` |
| `cache.py`, `semantic.py` | ключ меняется на (глагол, объект); правило отрыва остаётся как страховка |
| `resolver.py` | разделяется: разбор → связывание → решение по уверенности |
| `actions.py` | у действия появляются `undo` и «цена ошибки»; поиск цели уезжает в связывание |
| `llm.py` | остаётся; формат ответа меняется на (глагол, объект, уверенность) |

Ничего не выбрасывается целиком — меняется разрез.

## Порядок работ

1. **Журнал событий мира.** Без него заявленная цель недостижима, и он ни от чего не
   зависит — можно делать первым и сразу проверить на «открой то, что я вчера смотрел».
2. **Связывание как отдельный этап.** Механическое вынесение существующей логики;
   открывает единообразную обработку «какой именно».
3. **Уверенность и переспрос.** Малый объём, прямо снимает худший класс отказов.
4. **Разделение глагол × объект в кэше.** Самое крупное изменение; делать последним,
   когда вокруг устоялось.

## Риски и открытые вопросы

- **Морфология для русского может оказаться дорогой** на двух ядрах. Проверить
  замером до того, как закладываться на разделение глагол × объект.
- **Журнал событий — это слежка за собой.** Он пишет, что ты открывал и копировал.
  Хранить локально, не отправлять в LLM целиком (только релевантную выборку),
  предусмотреть выключение и очистку.
- **Переспрос может раздражать сильнее, чем ошибка.** Порог придётся подбирать живым
  использованием; пока нет данных, какая доля переспросов терпима.
- **Метрика.** Нынешняя («одно правильное действие») занижает качество и мешает
  сравнивать: часть «ошибок» в E2/E6 были разумнее эталона. Нужна разметка
  допустимых действий до того, как сравнивать модели дальше.
- **Всё ещё нет живого микрофона.** Все цифры по распознаванию — на синтезированной
  речи. Реальный WER может сдвинуть приоритеты целиком.
